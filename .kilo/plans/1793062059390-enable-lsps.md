# Enable LSPs Plan

## Goal
Configure Language Server Protocol (LSP) support for both Python (backend) and TypeScript (frontend) to enable IDE features: go-to-definition, hover info, diagnostics, completions, refactoring.

## Current State
- **Python backend**: FastAPI, uses `ruff` for linting/formatting (pyproject.toml)
- **TypeScript frontend**: React + Vite, uses `typescript` package (includes `tsserver`), strict mode enabled
- No existing LSP config files (pyrightconfig.json, .vscode/settings.json)

## Decisions

### Python LSP: ruff-lsp (Recommended)
**Rationale**: Project already uses `ruff` for linting. `ruff-lsp` is from the same team, shares the same parser/rules, zero-config, fast, and provides diagnostics + completions + hover + go-to-definition.

Alternative: `pyright` — more mature type checking, but requires config and duplicates linting rules.

### TypeScript LSP: Built-in tsserver (Default) + vtsls (Optional)
**Rationale**: `typescript` package already installed includes `tsserver`. Works out of the box with existing tsconfig. `vtsls` is a drop-in replacement with better performance/features but not required.

## Tasks

### 1. Add Python LSP config (ruff-lsp)
- Create `pyrightconfig.json` at repo root (for pyright-based tools) OR rely on ruff-lsp auto-detection from `pyproject.toml`
- **Recommended**: No extra config needed — ruff-lsp reads `[tool.ruff]` from `pyproject.toml` automatically
- Verify: Install `ruff-lsp` in dev env, test with `ruff-lsp --version`

### 2. Verify TypeScript LSP works
- `tsserver` is included in `typescript` devDependency
- Existing `tsconfig.json` + `tsconfig.app.json` + `tsconfig.node.json` provide project references
- No config changes needed — LSP activates automatically in editors

### 3. (Optional) Add VS Code workspace settings for consistent LSP behavior
Create `.vscode/settings.json`:
```json
{
  "python.languageServer": "Pylance",
  "python.analysis.typeCheckingMode": "basic",
  "[python]": { "editor.defaultFormatter": "charliermarsh.ruff" },
  "[typescript][typescriptreact]": { "editor.defaultFormatter": "esbenp.prettier-vscode" },
  "editor.codeActionsOnSave": {
    "source.fixAll.ruff": "explicit",
    "source.fixAll.eslint": "explicit",
    "source.organizeImports": "explicit"
  }
}
```
**Note**: Requires VS Code extensions: `charliermarsh.ruff`, `esbenp.prettier-vscode`, `ms-python.pylance`

### 4. Add ruff-lsp to dev dependencies (optional, for CI/local testing)
- `pip install ruff-lsp` or add to `pyproject.toml` `[project.optional-dependencies] dev`

### 5. Validate
- Open project in VS Code / Neovim / Helix with LSP client
- Verify Python: hover on FastAPI imports, go-to-definition on app modules, ruff diagnostics appear
- Verify TypeScript: hover on React components, go-to-definition on API types, tsserver diagnostics appear

## Out of Scope
- Neovim/Helix/Vim-specific LSP client config (user responsibility)
- Pyright strict type checking config (can be added later if needed)
- vtsls migration (tsserver works fine)
