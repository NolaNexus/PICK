# PICK — Items Overhaul Plan

## Goal

Make the Items data complete, clean, and presentable:

1. Every parseable wiki item is scraped — starting with the 20 potions that are currently missing.
2. No item text field contains raw wikitext (`[[links]]`, `{{templates}}`, `&nbsp;`, `<span>`).
3. Stat-like data is structured into one shared `StatModifier` shape so it can be displayed and used by calculators.
4. Item details are shown with bespoke per-shape components instead of a raw JSON dump.
5. Item images actually display.

## Decisions (resolved with the user)

1. **Scope**: full overhaul — parsers, data shape, detail UI, and a coverage check.
2. **Wikitext cleanup**: one central renderer applied at persist time, not per-parser and not in the browser.
3. **Stat schema**: one `StatModifier` shape applied to **everything with a stat-like field** (potions, equipment, mastery, modifiers, quests, museum ores, enchantments, runes).
4. **Detail UI**: bespoke components — **one per distinct data shape**, shared across types that share a shape (~18 components, not 29).
5. **Coverage**: a coverage report script that runs on **every daily scrape** (report-only, never fails the job).
6. **Migration**: bump a `schema_version` in the snapshot; the client discards a cached snapshot whose version differs; all detail components treat fields as optional.
7. **Images**: resolve filenames to real URLs at scrape time with batched `imageinfo` calls.

## Phase 1 — Central wikitext renderer (foundation)

New `scrapers/wikitext.py`:

1. `render_text(value: str) -> str`
   - Expand a **template map** first (value templates): `$`→`$N`; `Meteor Shards`→`N Meteor Shards`; `EXP`→`N EXP`; `Sand Dollars`/`Eggs`/`Candy`/`Heart Crystals`→`N <Name>`.
   - `stat`/`Stat` → argument 1 (the stat name).
   - Rarity templates (`common`, `rare`, `epic`, `legendary`, `mythic`, `exotic`, `uncommon`) → Title Case.
   - Unknown template **with no arguments** → the template name with underscores → spaces (covers all `{{Location}}` and item templates).
   - Unknown template **with arguments** → join non-named arguments with a space (never leak `key = value` pairs).
   - Wikilinks: `[[Target]]` → label (`Target` without any `#section`); `[[Target|Label]]` → `Label`.
   - External links `[url label]` → `label`.
   - Strip HTML tags (`<sup>`, `<span …>`, `<i>`, `<ref>`, `<br>`→newline); unescape entities (`&nbsp;`→space, `&times;`→`×`, `&amp;`→`&`); percent-decode (`%26`→`&`).
   - Strip residual table/markup artifacts: leading `|`, `|-`, `style="…"`, `'''`/`''`, trailing `="`/`=`.
   - Collapse whitespace; drop empty bullet lines.
2. `render_image(value: str) -> str | None` — first token before `|`, strip a `File:` prefix.
3. `render_item_data(data: dict) -> dict` — walk the dict, applying `render_text` to strings and `render_image` to `image`/`icon` keys, recursing into lists/dicts. Non-strings untouched. Preserve keys that are machine values: `color`, `slug`, `item_slug`, `npc_slug`, `*_url`, and any numeric fields.
4. Call `render_item_data` in `app/services/scraper.py` immediately before upsert, so every parser benefits and the existing 324 items are fixed by re-scraping.

**Parse-time fix (structure, not markup):** repair `scrapers/blueprints.py` so `quest_steps` is parsed from the real template parameters (`QuestSub`, `QuestStep1..N`, `Rewards`) into fields, instead of one raw blob.

New tests: `tests/test_wikitext.py` covering every template in the inventory, link forms, entities, image options, and the artifact cases listed above.

## Phase 2 — Shared `StatModifier` schema

Canonical shape (emit as `stats: [StatModifier]`):

```json
{ "stat": "Dig Speed", "amount": 20, "amount_max": 60,
  "unit": "flat|percent|multiplier", "duration_min": 10, "stage": 6,
  "condition": "at night" }
```

- **Emit `stats`** for: `potion` (Effect cell), `equipment` (replace the positional `stat1/val1/s6val1…` dict; `s6val` → `stage: 6`; `"0.3 – 0.8"` → `amount`/`amount_max`), `museum_ore` (`bonus_stat` + `max_boost`), `modifier` (`sell_price_multiplier`, `museum_bonus`, location/event boosts), `mastery` (from `boost_type`/`rewards`), `quest` (`buffs`), `enchantment` (`effects`), `rune` (description).
- **Only emit a modifier when a strict pattern matches** (sign, number, optional `%`/`×`, known stat name). Otherwise omit `stats` and keep the rendered text. Prose-heavy types (rune, enchantment, mastery) are best-effort by design.
- **Keep** existing clean scalars that other code depends on: `rarity` (required by the museum optimizer), `tier`, `value`, `min_kg`, `bonus_stat`, `max_boost`, and the rendered human text.
- Move the duplicated `_slugify` into the shared module while adding it (opportunistic, low risk).

Tests: extend each affected parser test (`test_equipment.py`, `test_mastery.py`, `test_modifiers.py`, `test_quests.py`, `test_museum.py`, `test_enchanting.py`, `test_runes.py`) with structured-`stats` assertions and a no-match fallback case.

## Phase 3 — Potions

1. New `scrapers/potions.py` (`parse_potions`): for each `== <Merchant> ==` section, parse the following wikitable. Emit type `potion` with:
   - `description`, `image` (filename), `effect` (rendered text), `stats` (from Phase 2), `duration_min`;
   - `cost_cash` / `cost_shards` (both may be set — e.g. `"$200,000,000 / 200 shards"`), plus `cost_text`;
   - `sold_by` = the section heading (e.g. `Fortune River Town Alchemist`), `source_location` when the section prose names a location.
   - Slug `potion-<name>`.
2. Register `"Potions": potions.parse_potions` in `scrapers/registry.py`; add `"Potions"` to `TRACKED_PAGES`.
3. `scrapers/traveling_merchant.py:_classify_item_type`: names ending in `"potion"` → `merchant_item` (not `potion`), so `reconcile_items` merges the listing into the canonical Potions-page row. Keep `enchant_book` as-is.
4. `app/services/reconcile.py:161-168`: restrict the "merchant-native canonical" branch to `enchant_book`, so a potion's static `cost_cash` is not mislabelled as a merchant listing.
5. Verify the 3 existing potions become canonical rows with a merged `merchant` block, not duplicates.

Tests: `tests/fixtures/Potions.wiki` (real wikitext) + `tests/test_potions.py` (asserts 20 potions, correct costs/effects/`sold_by`, and the cash-or-shards cases); a reconciliation test asserting merchant potion rows merge rather than duplicate.

## Phase 4 — Item detail UI

New `frontend/src/components/item-detail/`, one component per shape plus a type→component registry:

`ToolDetail` (pan/shovel/sluice), `EquipmentDetail`, `MineralDetail`, `MuseumOreDetail`, `PotionDetail`, `RelicDetail`, `QuestDetail`, `MasteryDetail`, `BlueprintDetail`, `RuneDetail`, `EnchantBookDetail`, `EnchantmentDetail`, `FormulaDetail`, `NPCDetail`, `LocationDetail`, `EventDetail`, `TreasureDetail` (chest/map), `MuseumDetail` (museum_display/museum_info), `ExcavationDetail` (site/level/reward), `GeodeDetail`, `ModifierDetail`, `TrinketDetail`, and a `FallbackDetail` (unknown type / `merchant_item`) that lists remaining keys.

- Every field optional; render nothing when absent; never throw on a partial payload.
- Render `stats` through one shared `<StatList>` component so the schema displays consistently.
- Use `image_url` when present, else a placeholder.
- Replace the raw JSON dump in `ItemBrowserPage.tsx:315-334`; apply the same component in `SearchPage.tsx` where it offers a View action.

## Phase 5 — Image URLs

- In `app/services/scraper.py` (or a small `app/utils/mw_api.py` helper), collect the distinct image filenames produced by a page and resolve them with batched `action=query&titles=File:A|File:B|…&prop=imageinfo&iiprop=url` (≤50 titles per call), storing the URL in the item's `image_url`.
- Cache per scrape run; tolerate missing files (leave `image_url` null).

## Phase 6 — Coverage report

- New `scripts/coverage_report.py`: for each `TRACKED_PAGES` entry, fetch wikitext, count wikitable data rows (`|-`), and compare with the parser's item count; also scan `allpages` for pages containing item-like tables that are absent from `TRACKED_PAGES`.
- Output a Markdown table; write it to `$GITHUB_STEP_SUMMARY` when set.
- **Report-only**: exit 0 on gaps; non-zero only on a hard failure (network/parse crash). It must not gate the job, because row-counting is heuristic and the wiki is external.
- Add a step to `.github/workflows/daily-scrape.yml` after the scrape and before the export.
- Run it during implementation to confirm Potions is the main gap and to surface any others (candidate follow-ups: `Permanent Buffs`, `Mythic`/`Codes` pages already partially tracked).

## Phase 7 — Snapshot schema version

- Add `"schema_version": 2` to `app/services/snapshot.py:build_snapshot`.
- `frontend/src/lib/snapshot.ts`: include the version in the `SnapshotData` shape and `normalizeSnapshot`; store it in the IndexedDB cache record and discard a cached snapshot whose version differs.
- Bump the version whenever item data shapes change again.

## Risks

- **Over-structuring prose.** Mastery/rune/enchantment text resists reliable parsing. Mitigation: strict patterns only, omit `stats` when unsure, always keep the rendered text, and test the no-match path.
- **Global renderer collateral.** Applying `render_text` to every string could damage an unexpected field. Mitigation: a test asserting no `[[`, `{{`, `&nbsp;`, or `<span` survives in any item `data`; review the snapshot diff before committing.
- **Equipment `stats` shape change.** Breaks `test_equipment.py` and any consumer. Mitigation: update tests and the UI together; `schema_version` shields cached clients.
- **Duplicate potions.** If the Traveling Merchant rows are not reclassified, `Instability`/`Quake`/`Blitz` appear twice. Mitigation: Phase 3.3-3.5 plus an explicit reconciliation test.
- **Coverage false positives.** `|-` counting miscounts merged cells and nested tables. Mitigation: report-only, never gates CI.
- **Image resolution volume.** Naive per-item calls would be slow. Mitigation: batch by 50 titles, cache per run.
- Live-wiki tests must keep using the existing `requires_wiki` skip guard.

items to 0, and item details are now shown properly instead of as a truncated JSON dump.

### Results

- **Potions: 3 → 20**, each with its cost (cash and/or shards), effect, duration, description,
  image, the merchant that sells it and the location. The three the Traveling Merchant lists are
  no longer separate rows: the merchant's live stock is merged into the potion.
- **Raw wikitext: 324 items → 0.** The renderer expands templates, resolves links and strips
  HTML in one place, so every parser benefits.
- **Structured stats** on equipment, potions, museum ores, modifiers, masteries, quests,
  enchantments and runes. Only a modifier that matches a strict pattern is emitted.
- **315 items** now have a picture, resolved from the wiki's file names in one batch per page.
- **A detail view per kind of item**, sharing components between the types with the same shape.
- **A coverage report** that runs on every scrape.

### Defects found and fixed along the way

- The blueprint quest steps collapsed into one blob, because the field separator did not allow
  for the space before the equals sign the wiki writes.
- The relic description, obtainment and usage fields were cut short at the heading markers.
- The recipe's quality marker (`<sup>c</sup>`) was left orphaned; it now reads `(c)`.
- A change to a parser or to the renderer did not reach the data that was already stored, because
  a page is only re-parsed when its wikitext changes. The parser version is now part of the
  page hash.
