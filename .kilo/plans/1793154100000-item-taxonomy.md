# PICK — Item Taxonomy & Reorganization

## Goal

Turn 1023 flat, overlapping rows into a coherent, browsable dataset: one entry per real thing, a
named taxonomy with real parent groups, a landing page, and reference material in one place.

## Decisions (resolved with the user)

1. **Model and presentation both change.**
2. **Routes**: `/` is a landing hub; `/items`, `/minerals`, `/world` and `/calculators` are the
   browsing areas. `/news`, `/search` and `/meta` stay as they are. There is **no `/museum` and no
   `/formulas` route**.
3. **Items** is one page with a group selector (Gear | Consumables | Treasure) and a second row of
   type tabs, so each type stays separate inside its parent group.
4. **Gear** = pan, shovel, sluice, equipment, trinket, rune. **Consumables** = potion, enchant_book,
   relic. **Treasure** = geode, treasure_chest, treasure_map.
5. **Minerals are their own area**, filterable by Area (resolved through their sub-locations).
6. **World** has five separated sections: NPC, Quest, Location, Excavation Site, Event.
7. **Excavation Site folds in the reward table**; the items it drops stay in their own types.
8. **Formulas, Mastery and Mutations nest under Calculators** as tabs beside the existing
   calculators. They are reference material for the calculators, not a top-level area.
9. **Merges**: `museum_ore` → mineral, `blueprint` → equipment, `consumable` → relic,
   `excavation_reward` → the site's drop table, `mutation_catalyst` → equipment,
   `museum_display` + `museum_info` → the Museum sub-location.
10. **Abilities attach to what they apply to**: enchantments → tools, modifiers → minerals,
    mutations → equipment, mutation chances → the Mutations tab under Calculators.
11. Blueprints never exist without equipment, so that merge is always lossless.
12. **Geography is two levels**: an **Area** (the teleporter area — 17 of them, the Locations page's
    18 tabs minus the Museum) is the parent, and a **Sub-location** (34) is the child. Users look up
    sub-locations, not areas.
13. **Minerals attach to sub-locations**, and each sub-location shows its mineral drop table with
    chances.
14. `Mysterious Meteors` is a wiki typo for `Mysterious Meteor (E-Site)`; alias it.
15. **The Museum is a sub-location of Caldera Park**, not an area of its own: the wiki lists it as a
    top-level tab, but `museum_info` says "Indoor location in Caldera Park". The 7 `museum_display`
    rows are its rarity display tiers, not separate museums, and belong on the Museum sub-location.

## Verified current state (evidence)

- **29 types, no registry.** Type strings are emitted ad hoc; nothing defines a group, label or
  whether a type is an item. The browser renders all 29 as flat, truncated filter buttons
  (`ItemBrowserPage.tsx:203`); the Search page repeats the same list (`SearchPage.tsx:160`).
- **185 names appear under more than one type**; 15 are exact duplicates within a type:
  `Adamantine` (mineral + museum_ore), `Accretion Disk` (blueprint + equipment), `Merchant` 8×.
- **Overlap is total where it matters**: 113 of 114 minerals have a museum row and every museum row
  has a mineral; **all 30** blueprints have equipment.
- **NPC rows duplicate by location**: 135 rows → 122 names, and `npc.data` already has a `locations`
  list, so the parser is fanning out per location.
- **Excavation site tiers are in the name**: `Volcanic Ruins (A-Site)`, `Lost City (D-Site)`.
  `excavation_level` gives item ranges per tier (`items_a_site`, `items_b_site`,
  `items_c_f_sites`). All 44 `excavation_reward` rows already carry `item_slug`.
- **One site name does not join**: drops say `Mysterious Meteors`, the site says
  `Mysterious Meteor (E-Site)`.
- **Mineral `locations` is a multi-line string in 108 of 114 minerals** (6 are arrays), so the Area
  filter needs it normalized to a list first. One value is corrupt: Pyrite's locations begin with a
  leftover `<div style="margin:0;">` wrapper.
- **Mineral location names are sub-locations, not areas**: there are 34 distinct mineral location
  names and exactly 34 sub-locations in the Locations page, and the names match (`Volcanic Sands`,
  `Volcanic Springs`, `Windswept Beach`, `Magma Furnace`, `Infernal Heart`, …). The join is total,
  and the 18 Location records are the parent **Areas** (one of which, the Museum, moves under
  Caldera Park), not a competing vocabulary.
- **The geography is two levels and is already on the wiki.** The Locations page has two tabbers,
  `== '''Regular Areas''' ==` and `== '''Limited Time Areas''' ==`. Each tab is an **Area** (the
  teleporter area — Caldera Park, Fortune River, …) and contains `; {{Sub-location}}` entries with a
  `* NPCs:` line, a picture, notes, and a `{{Name}} - '''Toughness N'''` line.
- **The current Locations parser throws the structure away**: `scrapers/locations.py` reads only the
  tab name and skips every `; {{…}}` block (`locations.py:76`), which is why `minerals` is empty on
  every location record and there is no sub-location data at all.
- **Mastery is a per-area ladder**: 56 rows shaped `Area Mastery: 1…N…Complete`, each with `steps`
  (conditions) and the boost it grants.
- **The Museum is already described as being in Caldera Park**: `museum_info` reads "Indoor location
  in Caldera Park where players place minerals into display pedestals…" and carries
  `location: "Caldera Park"`, even though the Locations page gives it its own tab. Making it a
  Caldera Park sub-location is therefore a curated override backed by the wiki's own text.
- **`museum_display` is not a list of museums**: it is 7 rarity tiers (Common, Uncommon, Rare,
  Epic, Legendary, Mythic, Exotic), each with free/locked display counts, a money price, a shard
  price and a total. Those belong on the Museum sub-location, not in a browsing area.
- **Events** carry `category` (regular / limited-time), a description and effects, and are spawned
  by relics at locations.
- **Mutations are real but unregistered**: `scrapers/mutations.py` has `parse_mutations`, 7 passing
  tests and a fixture, but `PARSERS["Mutations"] = None`. Catalysts come from `{{Mutations Row}}`
  with `equip name` and `mineral name`, so they belong to equipment.
- **Formulas exist twice**: `snapshot.formulas` (8 calculator formulas, read by the calculators) and
  27 `formula` items from `Stat_Systems_Guide`.
- **The museum calculator is safe**: it keys ores by `name|rarity` from any item with `data.rarity`
  (`CalculatorsPage.tsx:289`), and a mineral already carries `rarity`.
- **The mobile menu button is dead** (`<button className="md:hidden">` has no handler), so the nav
  cannot be used on a small screen.

## Phase 1 — Canonical taxonomy

1. New `app/taxonomy.py`: one entry per type with `{area, group, label, kind, order, hidden}` where
   `kind ∈ {item, record, reference}`. `area` is the route, `group` is the parent inside Items
   (Gear/Consumables/Treasure) or None. Export `areas()`, `groups(area)`, `types_in(...)`,
   `label(type)` and `is_listed(type)`.
2. Add `taxonomy` to `build_snapshot` (`app/services/snapshot.py`).
3. Add `GET /api/v1/taxonomy` and optional `?area=`/`?group=`/`?type=` filters on the items endpoint.
4. Frontend `src/lib/taxonomy.ts` reads `snapshot.taxonomy` with a safe fallback (humanised type,
   area `items`) for an unknown type.

## Phase 2 — Consolidate the data

All merges follow the existing `reconcile.py` pattern (merchant listings are already merged into
canonical items and deactivated) and must be idempotent. Every merge leaves and reports an
unmatched row instead of dropping it.

1. **`museum_ore` → `mineral`**: `mineral.data.museum = {min_weight_kg, max_boost, bonus_stat,
   rarity}`; deactivate the museum row.
2. **`blueprint` → `equipment`**: `equipment.data.blueprint = {quest_giver, quest_name, quest_steps,
   event_shop, purchase_info}`; deactivate.
3. **`consumable` → `relic`**: reclassify Firefly Flare and Traveler's Backpack as `relic` and
   re-slug them (`consumable-*` → `relic-*`); the existing merchant merge then attaches the stock.
4. **`excavation_reward` → `excavation_site`**: `site.data.drops = [{item_slug, chance, activation,
   description}]`; deactivate the reward rows. Join on the site name with the `(X-Site)` suffix
   stripped, and with a single alias for `Mysterious Meteors` → `Mysterious Meteor`.
5. **`excavation_level`**: keep the rows as `reference`; show the ladder (level, item ranges per
   tier, speed, durations) inside the Excavation Site section.
6. **`mutation_catalyst` → `equipment`**: match on `data.equipment`;
   `equipment.data.catalyst = {mineral, rarity}`; deactivate.
7. **NPC duplicates**: emit one row per name, merging `locations` into one list. If two rows of the
   same name differ in more than location, keep both with a location-suffixed slug.
8. **Normalize `mineral.data.locations` to a list**: split the multi-line string, keep arrays, drop
   lines that are only an HTML tag (Pyrite's `<div style="margin:0;">`), trim and de-duplicate.
   This is what makes the Area filter possible.
9. **`museum_display` + `museum_info` → the Museum sub-location**: put the 7 rarity display tiers
   under the Museum sub-location's `displays` and the blurb/staff/extras under its `info`, then
   deactivate both types. This runs after Phase 3 creates the Museum sub-location.

## Phase 3 — Geography: Area → Sub-location

1. Rewrite `scrapers/locations.py`:
   - Record which heading precedes each tabber: `Regular Areas` → `category: "regular"`,
     `Limited Time Areas` → `category: "limited_time"`.
   - Each tab is an **Area**: `name`, `description`, `image`, `sublocations`.
   - Each `; {{Name}}` block is a **Sub-location**: `name`, `slug`, `toughness` (from the
     `{{Name}} - '''Toughness N'''` line), `npcs` (from `* NPCs:`), `notes` (its bullets), `image`.
   - Store them as `location.data.sublocations` and `location.data.category`. Do **not** add a new
     item type: a sub-location is a child of its Area.
2. Resolve each mineral's `locations` to a sub-location and keep the parent Area names on the
   mineral, so the Minerals page can filter by Area without a join at render time. Report any name
   that matches no sub-location.
3. **Museum override**: the Locations page gives the Museum its own tab, but `museum_info` places it
   inside Caldera Park. Move that tab's `; {{Museum}}` sub-location into Caldera Park's child list
   and drop the standalone "Museum" area, leaving 17 Areas and 34 sub-locations (Museum included).
   Keep the override in one visible constant so it is easy to confirm or reverse, and tolerate a
   sub-location with no `Toughness` line (the Museum has none).
4. The sub-location **drop table is derived, not scraped**: every mineral whose `locations` include
   that sub-location, with its `chances` (`chance_percent`, `one_in`).

## Phase 4 — Enable mutations

1. Register `PARSERS["Mutations"] = mutations.parse_mutations`.
2. `mutation_effect` → `reference`, shown in the equipment Mutations section (with multipliers).
3. `mutation_chance` → `reference`, shown on the **Calculators → Mutations** tab. Attach a chance
   table to an equipment rarity only when the page makes that unambiguous; otherwise keep it
   unattributed rather than guessing.

## Phase 5 — Frontend

1. **Home** `/`: intro, search box, and cards linking to Items, Minerals, World, Calculators and News
   with their counts, plus game version and data-updated time.
2. **Items** `/items`: group selector (Gear | Consumables | Treasure) then type tabs; one table and
   detail dialog per type, reusing the existing components.
3. **Minerals** `/minerals`: list plus an Area filter built by resolving each mineral's sub-locations
   to their parent area; the specific sub-location is shown on each mineral.
4. **World** `/world`: sections NPC, Quest, Location, Excavation Site, Event.
   - **Location** is Areas (parent) → sub-locations (children). A sub-location shows its Toughness,
     NPCs, picture, notes, and its **mineral drop table** with chances.
   - **The Museum** is a Caldera Park child and shows its 7 rarity display tiers with prices, plus
     its info, staff and extras.
   - **Excavation Site** shows its costs, duration, its level ladder, and its drop table (each drop
     linking to its item).
5. **Calculators** `/calculators`: tabs **Calculators | Formulas | Mastery | Mutations**.
   - Formulas holds the calculator formulas and the 27 documented formulas.
   - Mastery is grouped by area, each ladder with its conditions and boost.
   - Mutations holds the chance tables.
6. **Detail sections**: equipment gains blueprint, catalyst and mutations; minerals gain museum data
   and a collapsed shared Ore modifiers list; tools gain a collapsed Enchantments list filtered by
   `applies_to`; the relic view already fits the two reclassified items.
7. **Search**: group + type filters driven by the taxonomy; still searches every area.
8. **Nav**: Home, Items, Minerals, World, Calculators, News, Search, Status. Remove the Museum and
   Formulas destinations and implement the existing dead hamburger for small screens.

## Phase 6 — Rollout

1. Bump `PARSER_VERSION` and `SNAPSHOT_SCHEMA_VERSION` to **4** in `app/services/snapshot.py` and
   `frontend/src/lib/snapshot.ts`.
2. Re-scrape, run reconciliation (the Phase 2 merges), export the snapshot.
3. Update `scripts/coverage_report.py` and `scripts/coverage_allowlist.json` for the new areas and
   the now-registered Mutations page.
4. Commit, push, verify CI and the Pages deploy.

## Risks

- **Site-name join.** `Mysterious Meteors` does not match `Mysterious Meteor (E-Site)`. Mitigation:
  normalize the suffix and carry an explicit alias; report any drop that fails to join.
- **Mineral area mapping.** `locations` is a string in 108 minerals. Mitigation: normalize to a list
  in the parser and add a test that every mineral has a list.
- **Relic reclassification.** Changing `consumable` to `relic` changes slugs. Mitigation: let the
  existing soft-delete/recreate path handle it and check both items keep their data.
- **Mutation chance attribution.** The rarity of each chance table may not be readable. Mitigation:
  attach only what is certain.
- **NPC merging merges genuinely different NPCs.** Mitigation: merge only when the rows differ by
  location alone; otherwise keep both with a location suffix.
- **Nav crowding.** Eight destinations. Mitigation: implement the mobile menu; keep the bar to the
  primary set if it still overflows.
- **The Museum override disagrees with the wiki's own layout.** The Locations page lists Museum as a
  top-level tab while `museum_info` says it is in Caldera Park. Mitigation: keep the override in one
  constant, state why in a comment, and make it easy to reverse.
- **Cached clients.** Shape changes. Mitigation: the schema version bump already discards an older
  cached snapshot.

   there is no `/formulas` or `/museum` route.
